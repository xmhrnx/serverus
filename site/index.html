Serverus connects to your machines over SSH, Telnet, FTP or right here on this computer, then watches them, opens terminals, moves files and runs the chores: processes, services, Docker, power and drives.

Connect

Four ways in, one sidebar.

Any number of servers in a searchable sidebar, grouped, tagged and colored, with live connection status. Right-click one to connect, reconnect, wake, edit or duplicate it, and test a connection before you save it.

SSHpassword, key, agent, one-time codes, jump hosts
Localthis computer, on any OS
Telnetswitches, routers, boards
FTP/Sfiles, with explicit TLS

Secrets stay in the keychain

Passwords and passphrases go to the OS keychain (Keychain, Credential Manager, Secret Service), never into the workspace file. Host keys are checked against known_hosts, new ones confirmed by fingerprint, and changed ones flagged.

SSH agents you already use

ssh-agent, the Windows OpenSSH agent, 1Password and Secretive. Chain jump hosts like ssh -J, and get notified when a server drops.

Files over SFTP, FTP or locally

Breadcrumbs, filters and sorting. Drop files and folders on the window to upload; transfers run in the background with progress, speed and cancel. Edit text files in place, and when root owns a file, Serverus offers to do it through sudo.

Administration without the incantations

  • Processes: sort, filter, terminate, kill or SIGHUP.
  • Services (systemd): start, stop, enable at boot, read the journal.
  • Docker: containers with live CPU and memory, logs, start and stop.
  • Power: restart, shut down or schedule it; wake again with Wake-on-LAN.
  • Drives: mount, unmount and eject USB drives.

Tunnels

Local port forwarding through any SSH server (ssh -L), opened by hand or on connect, with live connection counts.

Snippets

Saved commands: run on the current server, type into its terminal, or run on several servers at once and compare the results side by side.

Monitoring

Nothing to install on the server.

Linux servers are watched over SSH as they are, and this computer on any OS. Live charts cover the last few minutes, and each connected server's CPU shows in the sidebar.

CPU, memory, load

Total, I/O wait and per core; memory and swap, load, uptime and process count.

Disks and network

Every mounted file system, disk read and write, throughput per interface and in total.

Temperatures

From hwmon and thermal zones, colored by each sensor's high and critical thresholds.

Dashboards made of cards

An overview of every server (Ctrl/⌘+0) with a tile per server, what needs attention, shared CPU and memory history and rankings; and a per-server overview with gauges, history charts and small versions of the processes, services and containers pages. Make cards small, half or full width, move them, add or remove them; layouts are saved in the workspace.

The bars above are decoration, not data.

Terminal

A real terminal, in tabs.

  • xterm-256color with true color, wide characters and the alternate screen, so vim and htop look right.
  • Selection, copy and bracketed paste: Ctrl+Shift+C / V, or ⌘+C / V on macOS.
  • Scrollback with the mouse wheel or Shift+PageUp.
  • Insert saved snippets from the toolbar.

Everywhere

Native on the desktop, at home on a phone.

Built in Go with Giode: GPU-rendered, no webview. Start at login straight into the tray, keep running there when the window closes on Windows and macOS, and switch pages with Ctrl/⌘+1–8. The layout adapts down to phone width, where the server list becomes a drawer.

Dark and light

Or follow the system. Pick the background tone (emerald, graphite, midnight, plum, black) and the accent color in Settings.

Your data, your folder

The workspace lives in the platform's configuration folder; set SERVERUS_DATA_DIR for a portable install.

Privacy policy

Your servers, your device.

Serverus has no account, no analytics, no ads and no tracking. It connects only to the servers you add, and everything it keeps stays on your device. This policy covers Serverus on every platform and from every store.

What we collect

Nothing. Serverus never sends anything to its developer or to any third party: there is no telemetry, crash reporting, update check or advertising code in the app.

Where it connects

Only where you point it: the SSH, Telnet and FTP servers you add, the jump hosts you set, and the tunnels you open. Wake-on-LAN sends a wake-up packet on your local network. What you type and transfer goes straight between your device and your servers.

What stays on your device

  • Your workspace: servers (name, address, port, user name, key file location, group, tags, notes, color, MAC address), snippets, tunnels, settings and dashboard layouts, in the app's data folder.
  • Host keys you trust, in Serverus's own known_hosts file. It also reads your ~/.ssh/known_hosts where it can.
  • A copy of a private key file you pick, only on Android and in the Mac App Store version, which can't reopen your own file later. It stays in the app's private data folder.
  • Monitoring history, kept in memory for a few minutes and never written to disk.

Passwords and keys

Passwords and key passphrases you save go into the system's secure storage (Keychain on macOS, Credential Manager on Windows, Secret Service on Linux, Android Keystore), never into the workspace file.

A sudo password is kept in memory only, until you disconnect. Private keys are read from the file you choose and never leave your device; an SSH agent signs for you without handing its keys to Serverus.

Permissions

  • Network, to reach your servers.
  • Notifications, to tell you when a server disconnects (you can turn this off in Settings).
  • Files you choose, for uploads, downloads and key files.

Deleting your data

Delete a server and its saved password and passphrase go with it. Uninstalling the app, or deleting its data folder, removes the rest. Nothing is kept anywhere else, so there is nothing for us to delete.

Children, changes and contact

Serverus is a tool for administering computers and isn't directed at children. If this policy changes, the new version is published on this page with a new date. Questions go to the project's issue tracker.
